7.2 Metropolis-Hastings

Let q(Y∣X)q(Y∣X) be a transition density for pp-dimensional XX and YY from which we can easily simulate and let π(X)π(X) be our target density (i.e. the stationary distribution that our Markov chain will eventually converge to). The Metropolis-Hastings procedure is an iterative algorithm where at each stage, there are three steps. Suppose we are currently in the state xx and we want to know how to move to the next state in the state space.

  1. Simulate a candidate value y∼q(Y∣x)y∼q(Y∣x). Note that the candidate value depends on our current state xx.

  2. Let α(y∣x)=min{π(y)q(x∣y)π(x)q(y∣x),1}α(y∣x)=min{π(y)q(x∣y)π(x)q(y∣x),1} α(y∣x)α(y∣x) is referred to as the acceptance ratio.

  3. Simulate u∼Unif(0,1)u∼Unif(0,1). If u≤α(y∣x)u≤α(y∣x), then the next state is equal to yy. Otherwise, the next state is still xx (we stay in the same place).

This three step process represents the transition kernel for our Markov chain from which we are simulating. Recall that the hope is that our Markov chain will, after many simulations, converge to the stationary distribution. Eventually, we can be reasonably sure that the samples that we draw from this process are draws from the stationary distribution, i.e. π(X)π(X).

Why does this work? Recall that we need to have the Markov chain generated by this transition kernel be time reversible. If K(y∣x)K(y∣x) is the transition kernel embodied by the three steps above, then we need to show that

π(y)K(x∣y)=π(x)K(y∣x).π(y)K(x∣y)=π(x)K(y∣x). We can write the transition kernel K(y∣x)K(y∣x) as

K(y∣x)=α(y∣x)q(y∣x)+1{y=x}[1−∫α(s∣x)q(s∣x)ds]K(y∣x)=α(y∣x)q(y∣x)+1{y=x}[1−∫α(s∣x)q(s∣x)ds] The function K(y∣x)K(y∣x) can be decomposed into two parts and we can treat each separately. First we can show that K(y∣x)π(x)=K(x∣y)π(y)α(y∣x)q(y∣x)π(x)=α(x∣y)q(x∣y)π(y)min{π(y)π(x)q(x∣y)q(y∣x),1}q(y∣x)π(x)=min{π(x)π(y)q(y∣x)q(x∣y),1}q(x∣y)π(y)min(π(y)q(x∣y),q(y∣x)π(x))=min(π(x)q(y∣x),q(x∣y)π(y))K(y∣x)π(x)=K(x∣y)π(y)α(y∣x)q(y∣x)π(x)=α(x∣y)q(x∣y)π(y)min{π(y)π(x)q(x∣y)q(y∣x),1}q(y∣x)π(x)=min{π(x)π(y)q(y∣x)q(x∣y),1}q(x∣y)π(y)min(π(y)q(x∣y),q(y∣x)π(x))=min(π(x)q(y∣x),q(x∣y)π(y))

The last line is trivially true because on both sides of the equation we are taking the minimum of the same quantities.

For the second part, let r(x)=[1−∫α(s∣x)q(s∣x)ds]r(x)=[1−∫α(s∣x)q(s∣x)ds]. Then we need to show that 1{y=x}r(x)π(x)=1{x=y}r(y)π(y)1{y=x}r(x)π(x)=1{x=y}r(y)π(y) over the set where y=xy=x. But this is trivially true because if y=xy=x then every quantity in the above equation is the same regardless of an xx or a yy appears in it.

7.2.1 Random Walk Metropolis-Hastings

Let q(y∣x)q(y∣x) be defined as

y=x+εy=x+ε where ε∼gε∼g and gg is a probability density symmetric about 00. Given this definition, we have

q(y∣x)=g(ε)q(y∣x)=g(ε)

and

q(x∣y)=g(−ε)=g(ε)q(x∣y)=g(−ε)=g(ε)

Because q(y∣x)q(y∣x) is symmetric in xx and yy, the Metropolis-Hastings acceptance ratio α(y∣x)α(y∣x) simplifies to

α(y∣x)=min{π(y)q(x∣y)π(x)q(y∣x),1}=min{π(y)π(x),1}α(y∣x)=min{π(y)q(x∣y)π(x)q(y∣x),1}=min{π(y)π(x),1}

Given our current state xx, the random walk Metropolis-Hastings algorithm proceeds as follows:

  1. Simulate ε∼gε∼g and let y=x+εy=x+ε.

  2. Compute α(y∣x)=min{π(y)π(x),1}α(y∣x)=min{π(y)π(x),1}

  3. Simulate u∼Unif(0,1)u∼Unif(0,1). If u≤α(y∣x)u≤α(y∣x) then accept yy as the next state, otherwise stay at xx.

It should be noted that this form of the Metropolis-Hastings algorithm was the original form of the Metropolis algorithm.

7.2.1.1 Example: Sampling Normal Variates

As a simple example, we can show how random walk Metropolis-Hastings can be used to sample from a standard Normal distribution. Let gg be a uniform distribution over the interval (−δ,δ)(−δ,δ), where δδ is small and >0>0 (its exact value doesn’t matter). Then we can do

  1. Simulate ε∼Unif(−δ,δ)ε∼Unif(−δ,δ) and let y=x+εy=x+ε.

  2. Compute α(y∣x)=min{φ(y)φ(x),1}α(y∣x)=min{φ(y)φ(x),1} where φφ is the standard Normal density.

  3. Simulate u∼Unif(0,1)u∼Unif(0,1). If u≤α(y∣x)u≤α(y∣x) then accept yy as the next state, otherwise stay at xx.

We can see what this looks like but running the iteration many times.

delta <- 0.5
N <- 500
x <- numeric(N)
x[1] <- 0
set.seed(2018-06-04)
for(i in 2:N) {
        eps <- runif(1, -delta, delta)
        y <- x[i-1] + eps
        alpha <- min(dnorm(y, log = TRUE) - dnorm(x[i-1], log = TRUE), 0)
        u <- runif(1, 0, 1)
        if(log(u) <= alpha)
                x[i] <- y
        else
                x[i] <- x[i-1]
}
summary(x)
##    Min. 1st Qu.  Median    Mean 3rd Qu.    Max. 
## -2.1314 -0.6135 -0.1485 -0.1681  0.3034  1.8465

We can take a look at a histogram of the samples to see if they look like a Normal distribution.

hist(x)

We can also look at a trace plot of the samples to see how the chain moved around.

library(ggplot2)
qplot(1:N, x, geom = "line", xlab = "Iteration")

What would happen if we changed the value of δδ? Here we make δδ bigger and we can see the effect on the trace plot.

delta <- 2
N <- 500
x <- numeric(N)
x[1] <- 0
set.seed(2018-06-04)
for(i in 2:N) {
        eps <- runif(1, -delta, delta)
        y <- x[i-1] + eps
        alpha <- min(dnorm(y, log = TRUE) - dnorm(x[i-1], log = TRUE), 0)
        u <- runif(1, 0, 1)
        if(log(u) <= alpha)
                x[i] <- y
        else
                x[i] <- x[i-1]
}
summary(x)
##     Min.  1st Qu.   Median     Mean  3rd Qu.     Max. 
## -2.60714 -0.72944 -0.05603 -0.07395  0.53416  2.51142

Now look at the trace plot.

library(ggplot2)
qplot(1:N, x, geom = "line", xlab = "Iteration")

You can see in this trace plot that there are a number of iterations where there is no movement (so that the candidate is rejected, whereas in the above trace plot with the smaller value of δδ there was much more movement, although the steps themselves were smaller. In particular, the first chain exhibited a bit more autocorrelation. With a larger δδ, we are proposing candidates that are much further from the current state, and that may not comport with the Normal distribution. As a result, the candidates are more likely to be rejected.

This raises an important in Markov chain samplers: tuning. The theory does not depend on a specific value of δδ; both chains above should converge to a Normal distribution. However, the speed with which they converge and amount of the sample space that is explored does depend on δδ. Hence, the sampler can be tuned to improve its efficiency.

7.2.2 Independence Metropolis Algorithm

The independence Metropolis algorithm defines a transition density as q(y∣x)=q(y)q(y∣x)=q(y). In other words, the candidate proposals do not depend on the current state xx. Otherwise, the algorithm works the same as the original Metropolis-Hastings algorithm, with a modified acceptance ratio,

α(y∣x)=min{π(y)q(x)π(x)q(y),1}α(y∣x)=min{π(y)q(x)π(x)q(y),1}

The independence sampler seems to work well in situations where rejection sampling might be reasonable, i.e. relatively low-dimensional problems. In particular, it has the interesting property that if

C=supxπ(x)q(x)<∞C=supxπ(x)q(x)<∞

then

∥πn−π∥≤kρn‖πn−π‖≤kρn for 0<ρ<10<ρ<1 and some constant k>0k>0. So if we have the same conditions under which rejection sampling is allowed, then we can prove that convergence of the chain to the stationary distribution is geometric with rate ρρ. The value of ρρ depends on CC; if CC is close to 11, then ρρ will be small. This is an interesting property of this sampler, but it is largely of theoretical interest.

7.2.3 Slice Sampler

Given the current state xx, generate

y∼Unif(0,π(x))y∼Unif(0,π(x))

Given yy, generate a new state x⋆x⋆

x⋆∼Unif({x:π(x)≥y})x⋆∼Unif({x:π(x)≥y})

Slice Sampler

Note that π(x)=∫1{0≤y≤π(x)}dy.π(x)=∫1{0≤y≤π(x)}dy. Therefore, f(x,y)=1{0≤y≤π(x)}f(x,y)=1{0≤y≤π(x)} is a joint density. The slice sampler method creates an auxiliary variable yy and the intergrates it out later to give back our original target density π(x)π(x).

As depicted in the illustration, the slice sampler can be useful for densities that might have multiple modes where it’s easy to get stuck around one model. The sampling of x⋆x⋆ allows one to jump easily between modes. However, sampling x⋆x⋆ may be difficult depending on the complexity of π(x)π(x) and ultimately may not be worth the effort. If π(x)π(x) is very wiggly or is high-dimensional, then calculating the region {x:π(x)≥y}{x:π(x)≥y} will be very difficult.

7.2.4 Hit and Run Sampler

The hit and run sampler combines ideas from line search optimization methods with MCMC sampling. Here, suppose we have the current state xx in pp-dimensions and we want to propose a new state. Let ee be a random pp-dimensional vector that indicates a random direction in which to travel. Then construct the density p(r)∝π(x+re).p(r)∝π(x+re). where rr is a scalar (and hence p(r)p(r) is a 1-dimensional density). From this density, sample a value for rr and set the proposal to be x⋆=x+re.x⋆=x+re. This process has teh advantage that it chooses more directions than a typical Gibbs sampler (see below) and does not require a multi-dimensional proposal distribution. However, sampling from the density p(r)p(r) may not be obvious as there is no guaranteed closed form solution.

7.2.5 Single Component Metropolis-Hastings

The standard Metropolis algorithm updates the entire parameter vector at once with a single step. Hence, a pp-dimensional parameter vector must have a pp-dimensional proposal distribution qq. However, it is sometimes simpler to update individual components of the parameter vector one at a time, in an algortihm known as single component Metropolis-Hastings (SCMH).

Let x(n)=(x(n)1,x(n)2,…,x(n)p)x(n)=(x1(n),x2(n),…,xp(n)) be a pp-dimensional vector representing our parameters of interest at iteration nn. Define x−i=(x1,…,xi−1,xi+1,…,xp)x−i=(x1,…,xi−1,xi+1,…,xp) as the vector xx with the iith component removed. The SCMH algorithm updates each paramater in xx one at a time. All that is needed to update the iith component of x(n)x(n) is a proposal distribution q(y∣x(n)i,x(n)−i)q(y∣xi(n),x−i(n)) for proposing a new value of xixi given the current value of xixi and all the other components.

At iteration nn, SCMH updates the iith component via the following steps.

  1. Sample yi∼qi(y∣x(n)i,x(n)−i)yi∼qi(y∣xi(n),x−i(n)) as a proposal for component ii.

  2. Let α(yi∣x(n))=min⎛⎝π(yi∣x(n)−i)q(xi∣yi,x(n)−i)π(xi∣x(n)−i)q(yi∣xi,x(n)−i),1⎞⎠α(yi∣x(n))=min(π(yi∣x−i(n))q(xi∣yi,x−i(n))π(xi∣x−i(n))q(yi∣xi,x−i(n)),1)

  3. Accept yiyi for component ii with probablity α(yi∣x(n))α(yi∣x(n)).

  4. Repeat 1–3 pp times until every component is updated.
